# Bead-forge to bead-rs agent-guided rehydration

Status: proven on isolated fixtures against bead-rs v0.1.3; fleet cutover is
blocked only on the NEEDLE staged-rollout gate.

This procedure follows bead-rs ADR-002. It is rehydration, not schema import:
the source is read through public `bf` commands, every destination mutation is
made through public `bead` commands, and every source ID receives a reviewed
reconciliation disposition. Never open a bead-forge SQLite file with `bead`,
write native SQLite directly, or synthesize a bead-rs checkpoint.

The executable proof is
`tests/bead_rehydration_verification.rs`. It covers a nontrivial source with
open, dependency-blocked, in-progress, deferred, and closed work; exact graph
comparison; ready-frontier equivalence; native checkpoint flush and clean
restore; source immutability; and rollback backup readability. Its verifier is
also proven to reject one omitted issue and one inverted edge.

## Release gates

Do not cut over a fleet repository until all of these are true:

1. The exact bead-rs build has the independently authored and approved
   ADR-002 field guide and supports
   `bead schema explain urn:bead-rs:schema:issue:native-v1`. Installed bead
   v0.1.3 (`85f36ac`) satisfies this gate. Help prose is not a substitute.
2. NEEDLE's descriptor-driven store, mixed-backend isolation, and real
   bead-rs lifecycle gates pass on the release candidate.
3. No source mutation or NEEDLE worker is active during the final capture and
   cutover window.
4. The repository's `origin` is its Forgejo source of truth and its worktree
   has no unrelated changes that the cutover would overwrite.
5. A reviewer has approved every `omitted`, `merged`, or `unresolved`
   disposition and every lossy field decision.

## Semantic mapping

| bead-forge field | bead-rs action | Reconciliation rule |
| --- | --- | --- |
| `id` | generated by `bead create` | Record exact source-to-native mapping; never preserve the old ID by writing storage. |
| `title` | `create --title` | Must match exactly. |
| `description` | `create --description` | Must match exactly; absent becomes empty. |
| `priority` | `create --priority` | Native range is 0–4. Any other value is `unresolved` until reviewed; do not clamp silently. |
| `issue_type` | `create --issue-type` | Preserve the public string. |
| `labels[]` | repeated `create --label` | Compare as a set after creation. |
| `assignee` | `create --assignee` or lifecycle `update --assignee` | Preserve when compatible with the target lifecycle. |
| `status=open` | create default | Preserve base open state. |
| `status=in_progress` | `update ID --status in_progress --assignee ACTOR` | Actor is required; missing source actor is unresolved. |
| `status=deferred` | `update ID --status deferred` | Preserve. |
| `status=closed/completed` | `close ID --reason REASON` | Preserve reason when present; otherwise record the explicit fallback in the report. |
| `status=blocked` with unfinished blocker edges | create open, then recreate edges | bead-forge projects derived blocking into status; bead-rs retains open base status and derives readiness. Verify ready-frontier equivalence. |
| edge-free `status=blocked` | `update ID --status blocked` | Treat as manual blocking and verify it stays out of `list --ready`. |
| `dependencies[]` | `bead dep add DEST_BLOCKED DEST_BLOCKER --kind KIND` | bead-rs is blocked-first. Compare complete canonical `(blocked, blocker, kind)` sets. |
| `notes`, `design`, `acceptance_criteria` | no equivalent create flag in the probed CLI | Merge into reviewed description text or mark omitted/unresolved; state the decision per issue. |
| comments and events/history | no equivalent public authoring surface in the probed CLI | Archive in the source snapshot and mark omitted unless a reviewed native public operation exists. |
| timestamps, revision, derived fields | native read-only fields | Mark omitted and let bead-rs author them. |

The running field guide is authoritative if it differs from this observed
mapping. A difference stops the run for review; it is never resolved by guessing.

## Reconciliation report

Keep the report outside `.beads/` during rehearsal. Scan it before committing.
Each source item has exactly one disposition:

```json
{
  "source_repository": "ssh://git.ardenone.com/jedarden/example.git",
  "source_commit": "<40-hex commit>",
  "source_cli": "bf 0.4.1",
  "destination_cli": "bead 0.1.3+85f36ac",
  "captured_at": "<UTC timestamp>",
  "issues": [
    {
      "source_id": "bf-abc",
      "disposition": "created",
      "destination_id": "example-1234abcd",
      "field_decisions": {
        "created_at": "omitted: native read-only",
        "notes": "merged into description after review"
      }
    }
  ],
  "edges": [
    {
      "source_blocked": "bf-def",
      "source_blocker": "bf-abc",
      "kind": "blocks",
      "destination_blocked": "example-5678efab",
      "destination_blocker": "example-1234abcd"
    }
  ]
}
```

Allowed dispositions are `created`, `merged`, `omitted`, and `unresolved`.
`created` requires a destination ID. `merged` names the destination and reason.
`omitted` and `unresolved` require a reviewable reason. Count equality applies
to `created` destinations after accounting for approved merges; silent absence
is always an error.

## Rehearsal

Use explicit absolute paths recorded in the run log. Temporary directories
belong under `/home/coding/scratch`.

1. Stop source writers. Record `git status --short`, `git rev-parse HEAD`,
   `git remote get-url origin`, `bf --version`, and `bead --version` without
   printing credentials.
2. Protect and inspect live source state:

   ```text
   bf sync --flush-only
   sqlite3 .beads/beads.db "PRAGMA integrity_check;"
   bf doctor
   bf list --all --limit 999999 --json
   bf ready --limit 999999 --json
   ```

   `bf list --json` and `bf ready --json` must be parsed as observed public
   JSON records, accepting either JSON lines or an array. `ready` is never the
   source inventory.
3. Copy the entire quiescent `.beads/` directory to a uniquely named rollback
   directory. Re-run `bf list --all` from the backup and require byte-equivalent
   canonical records before proceeding.
4. Create a separate destination directory. Run `bead init --prefix PREFIX`.
   For every source record, consult the field guide, choose a disposition,
   create through `bead create`, and immediately record the returned ID.
5. After all IDs exist, recreate every edge with the mapped IDs. The order is:

   ```text
   bead dep add DEST_BLOCKED DEST_BLOCKER --kind blocks
   ```

6. Apply lifecycle transitions only after edges exist. This prevents a
   dependency-blocked source item from being mistaken for a manually blocked
   item.
7. Enumerate all destination records with
   `bead list --json --limit 999999`, then use `bead show ID --json` where the
   field guide requires a detailed projection. Verify every created issue,
   every mapped field, and exact canonical edge-set equality. Compare the
   mapped `bf ready` set to `bead list --ready --json --limit 999999`.
8. Require `bead doctor` to pass. Run `bead sync flush-only`.
9. Rehearse a clean restore in another empty directory: copy only native
   `config.json` and the emitted `.beads/checkpoint/`, run `bead init`, then:

   ```text
   bead sync import-only --input .beads/checkpoint \
     --restore-into-empty --actor rehydration-rehearsal
   bead doctor
   ```

   Repeat the complete issue, field, graph, and ready-frontier verification.
10. Place source public records, the reconciliation report, and intended Git
    artifacts in a dedicated scan directory, then run the repository's
    configured secret scanner in redacted mode. With the fleet-standard
    `gitleaks` binary this gate is:

    ```text
    gitleaks detect --no-git --redact --source ABSOLUTE_SCAN_DIRECTORY
    ```

    A missing scanner or nonzero result blocks approval. Keep scanner output
    out of the repository, never print detected secret values, and resolve all
    findings before continuing.

Run the repository proof with:

```text
BF_BIN=/absolute/path/to/bf \
BEAD_RS_BIN=/absolute/path/to/bead \
cargo test --test bead_rehydration_verification -- --ignored --nocapture
```

## Cutover

Repeat the capture after stopping writers; do not reuse stale rehearsal data.
Require the final source capture to match the approved reconciliation input.
Then:

1. Preserve the final source `.beads/` rollback directory outside the path
   that will become live.
2. Move the fully verified native `.beads/` directory into the repository using
   a same-filesystem, reversible rename. Do not delete the source backup.
3. Merge this key into the existing `.needle.yaml` without replacing unrelated
   configuration:

   ```yaml
   bead_cli:
     backend: bead-rs
   ```

4. Run `bead doctor`, `needle doctor --workspace ABSOLUTE_REPOSITORY`, and one
   controlled NEEDLE claim/release or claim/close lifecycle.
5. Flush, inspect `git status --short`, scan intended artifacts, stage exact
   paths, commit to `main`, and push only to Forgejo `origin`.
6. Retain the reconciliation report and rollback location in the migration
   bead without recording credentials or secret contents.

## Rollback

Stop NEEDLE and all bead writers. Move the failed native `.beads/` directory
aside for diagnosis, restore the preserved source `.beads/` directory by
same-filesystem rename, restore the prior `.needle.yaml` backend binding, and
verify `bf doctor` plus the final captured `bf list --all` canonical hash.
Restart workers only after the source inventory and ready frontier agree with
the pre-cutover evidence. Never repair or delete either database as part of
rollback unless its own diagnostics and safety procedure explicitly require it.
