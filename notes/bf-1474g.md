# P95 Percentile Calculation Research (Bead bf-1474g)

## Current Implementation

NEEDLE currently uses a simple **nearest-rank method** in `src/sanitize/mod.rs`:

```rust
latencies.sort();
let median = latencies[SAMPLE_COUNT / 2];
let p95 = latencies[(SAMPLE_COUNT * 95) / 100];
```

For 20 samples (SAMPLE_COUNT = 20):
- median: latencies[10] (50th percentile)
- p95: latencies[19] (95th percentile)

This is a **nearest-rank** approach - it returns the actual data point at the calculated rank position.

## Methods Researched

### 1. Nearest-Rank Method
**Formula:** `rank = ceil(p × N)` or `rank = floor(p × N)`

**Advantages:**
- Simple to implement
- Always returns an actual observed value
- Deterministic
- No interpolation artifacts

**Disadvantages:**
- Can be coarse for small sample sizes
- Less accurate for continuous distributions
- Step-function behavior

**Implementation:** `data[(n * percentile) / 100]`

---

### 2. Linear Interpolation Between Closest Ranks
**Formula:**
```
h = p × (N - 1) + 1  # or h = p × N depending on convention
rank_lower = floor(h)
rank_upper = ceil(h)
fraction = h - rank_lower

percentile_value = data[rank_lower] + fraction × (data[rank_upper] - data[rank_lower])
```

**Advantages:**
- More accurate for continuous data
- Accounts for gaps between ranks proportionally
- Industry standard for statistical software
- Can estimate values between observed data points

**Disadvantages:**
- More complex calculation
- Can return values not present in original data
- Requires sorting (same as nearest-rank)

**Rust Implementation Sketch:**
```rust
fn percentile_linear(sorted_data: &[f64], p: f64) -> f64 {
    let n = sorted_data.len();
    if n == 0 {
        return 0.0;
    }

    let h = p * (n - 1) as f64;
    let lower = h.floor() as usize;
    let upper = h.ceil() as usize;
    let fraction = h - lower as f64;

    if lower == upper {
        return sorted_data[lower];
    }

    sorted_data[lower] + fraction * (sorted_data[upper] - sorted_data[lower])
}
```

## Recommendation

**Use linear interpolation** for p95 calculation in NEEDLE for the following reasons:

1. **Statistical accuracy**: Linear interpolation accounts for gaps between ranks proportionally
2. **Industry standard**: Most statistical software (numpy, scipy, R) uses this by default
3. **Better for small samples**: With only 20 samples, interpolation provides more accurate estimates
4. **Latency measurement context**: We're measuring continuous time values, not discrete categories

The implementation cost is minimal (requires sorting, same as current), and the accuracy gain is significant for latency metrics where precision matters.

## Implementation Plan

Replace current nearest-rank implementation with linear interpolation:

```rust
fn calculate_percentile(latencies: &mut [u128], percentile: f64) -> u128 {
    latencies.sort();
    let n = latencies.len();
    if n == 0 {
        return 0;
    }

    let h = percentile * (n - 1) as f64;
    let lower = h.floor() as usize;
    let upper = h.ceil() as usize;
    let fraction = h - lower as f64;

    if lower == upper {
        return latencies[lower];
    }

    let lower_val = latencies[lower] as f64;
    let upper_val = latencies[upper] as f64;
    (lower_val + fraction * (upper_val - lower_val)) as u128
}

// Usage:
let median = calculate_percentile(&mut latencies, 0.5);
let p95 = calculate_percentile(&mut latencies, 0.95);
```
