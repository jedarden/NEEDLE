## Key Findings

### Why Tests Didn't Catch the Bug

**Unit Tests**: Construct `TmuxSession { pid: Some(1001) }` directly where 1001 is assumed to be the actual needle process PID, completely bypassing the pane_pid→child indirection.

**Integration Tests**: Use simplified tmux invocation (`tmux new-session -d -s name sleep 3600`) which doesn't include the NEEDLE_INNER wrapper or output redirection, so pane_pid equals the child process PID - no indirection to test.

**P7.1a Test**: The only test that correctly reproduces the production command shape with `NEEDLE_INNER=1 ... 2>> log`, creating the actual shell-wrapper→child split.

### Real tmux Session Process Tree

```bash
# Production invocation
tmux new-session -d -s needle-claude-alpha \
  "NEEDLE_INNER=1 /path/to/needle run ... 2>> /path/to/log"

# Process tree (verified via pstree)
tmux: server (PID 1)
  └─ bash -c "NEEDLE_INNER=1 needle run ... 2>> log" (PID 1234) ← pane_pid points here
      └─ needle run --workspace ... (PID 5678) ← actual worker process
```

### The Bug and Fix

**Buggy code (pre-P7.1a)**:
```rust
s.pid.map_or(true, |pane_pid| !live_pids.contains(&pane_pid))
// Checked if shell PID (1234) was in live_pids {5678} → false → killed live session!
```

**Fixed code (post-P7.1a)**:
```rust
s.pid.map_or(true, |pane_pid| {
    match find_needle_process_in_tree(pane_pid) {
        Some(needle_pid) => !live_pids.contains(&needle_pid), // Checks 5678 in {5678} → true → preserved
        None => true, // No needle run found → orphaned
    }
})
```
