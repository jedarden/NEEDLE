## Config Struct Patterns

### Standard Derives
All config structs use:
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
```

### Default Implementation Pattern
```rust
impl Default for MyConfig {
    fn default() -> Self {
        MyConfig {
            field1: Self::default_field1(),
            field2: Self::default_field2(),
        }
    }
}

impl MyConfig {
    fn default_field1() -> Type { /* default value */ }
    fn default_field2() -> Type { /* default value */ }
}
```

### Serde Default Pattern
```rust
#[serde(default = "MyConfig::default_field")]
pub field: Type,
```

### Field Type Patterns
- **Primitives**: `String`, `u64`, `u32`, `u8`, `bool`, `f64`
- **Paths**: `PathBuf` for file/directory paths
- **Optional**: `Option<T>` for nullable fields
- **Lists**: `Vec<T>` with `#[serde(default)]`
- **Maps**: `BTreeMap<String, T>` for keyed collections
- **Nested structs**: Other config structs

### Path Handling Pattern
All paths support tilde expansion, expanded via `Config::expand_tildes()`:
```rust
fn expand_tilde(path: &Path) -> PathBuf
fn expand_tilde_vec(paths: &[PathBuf]) -> Vec<PathBuf>
fn expand_tilde_option(path: &Option<PathBuf>) -> Option<PathBuf>
```

- `agent`: Agent CLI configuration
- `worker`: Worker pool configuration  
- `workspace`: Workspace paths and labels

1. **Supervisor is infrastructure**: Like the agent and worker configs, it controls how NEEDLE runs
2. **Related to health**: Supervisor detection uses heartbeat files, similar to worker health monitoring
3. **Not overridable at workspace level**: Like `worker`, `limits`, `health`, and `telemetry`, supervisor config is global-only

## Key Learnings for Adding New Config

When adding new configuration sections, follow these patterns:

1. **Create the struct** with standard derives and `impl Default`
2. **Add static `default_*()` methods** for each field
3. **Use `#[serde(default)]`** for fields with `Default` impl
4. **Add to top-level `Config`** with `#[serde(default)]`
5. **Add path expansion** in `Config::expand_tildes()` if using PathBuf fields
6. **Add env var overrides** in `ConfigLoader::apply_env_overrides()` if needed
7. **Add validation** in `ConfigLoader::validate()` if needed
8. **Add comprehensive tests** following the existing test patterns
9. **Decide if workspace-overridable**: Add to `WorkspaceOverrides` if yes, add to `NON_OVERRIDABLE_KEYS` if no
10. **Document with doc comments**: Each field should have a clear explanation
